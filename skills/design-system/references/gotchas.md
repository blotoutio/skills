# Gotchas: API mistakes to avoid

The DS follows shadcn/ui naming but is built on **Base UI**, not Radix. Models trained on shadcn code
get these wrong most often. Two kinds:

- **Type errors** (typecheck catches them): wrong prop names, missing exports.
- **Compiles but broken** (typecheck does NOT catch them): marked ⚠️ below. Check these by eye.

## Composition: `render`, never `asChild`

```tsx
// Wrong (Radix/shadcn)
<DialogTrigger asChild><Button>Open</Button></DialogTrigger>

// Right (Base UI)
<DialogTrigger render={<Button variant='outline' />}>Open</DialogTrigger>
<DropdownMenuTrigger render={<Button variant='ghost' size='icon' aria-label='More actions' />}>
  <MoreHorizontalIcon />
</DropdownMenuTrigger>
<SidebarMenuButton isActive={pathname === '/reports'} render={<a href='/reports' />}>
  <ChartBarIcon /><span>Reports</span>
</SidebarMenuButton>
<Badge render={<a href='/billing' />}>Billing</Badge>
<CardTitle render={<h2 />}>Usage</CardTitle>
```

- ⚠️ `Button` rendered as a link needs `nativeButton={false}`:
  `<Button nativeButton={false} render={<Link to='/x' />}>Open</Button>`. Simpler for plain links:
  `<Link to='/x' className={buttonVariants({ variant: 'outline' })}>Open</Link>`.
- Router links elsewhere: `render={<Link to='/x' />}` (React Router) or `render={<NextLink href='/x' />}`.
- Some examples in `llms-full.txt` still show `asChild`. They're wrong; use `render`.

## react-hook-form

Native inputs register directly. Base UI controls (Select, Checkbox, Switch, RadioGroup, Combobox,
Slider, date pickers) need `Controller`, because they use `value`/`onValueChange`, not DOM events.

```tsx
// Give useForm defaultValues for every field (Base UI controls must start controlled).
const { register, control, formState: { errors } } = useForm<Values>({ defaultValues: { email: '', role: null, updates: false } })

<Field invalid={!!errors.email}>
  <FieldLabel>Email</FieldLabel>
  <Input type='email' {...register('email', { required: 'Enter an email address' })} />
  <FieldError match={!!errors.email}>{errors.email?.message}</FieldError>
</Field>

<Controller
  control={control}
  name='role'
  render={({ field, fieldState }) => (
    <Field invalid={!!fieldState.error}>
      <FieldLabel>Role</FieldLabel>
      <Select items={ROLE_LABELS} value={field.value ?? null} onValueChange={field.onChange}>
        <SelectTrigger><SelectValue placeholder='Choose a role' /></SelectTrigger>
        <SelectContent>
          {Object.entries(ROLE_LABELS).map(([value, label]) => <SelectItem key={value} value={value}>{label}</SelectItem>)}
        </SelectContent>
      </Select>
      <FieldError match={!!fieldState.error}>{fieldState.error?.message}</FieldError>
    </Field>
  )}
/>
```

Checkbox/Switch: `checked={!!field.value} onCheckedChange={field.onChange}`. Never pass `undefined` as a
controlled value: `value={field.value ?? null}` for Select/Combobox/RadioGroup, or `reset()`/`setValue()`
won't show (Base UI treats the first `undefined` as uncontrolled).

## Keyboard shortcuts are display-only

The DS never binds keys. Display parts: the `shortcut` prop on `ContextMenuItem` /
`ContextMenuCheckboxItem` / `ContextMenuRadioItem` and on `CommandPalette` items; `keys` on
`TooltipShortcut`; child components `<DropdownMenuShortcut>`, `<MenubarShortcut>`, `<CommandShortcut>`.
The app wires hotkeys itself (e.g. TanStack Hotkeys) and passes the label in. Don't show a hint for a
shortcut the app doesn't handle.

## Next.js App Router

The package is `"use client"`. DS components render fine from server components, but calling helpers
(`cn`, `buttonVariants`, `formatMetric`, `formatDateLabel`) inside a server component throws: call them
in a `'use client'` file. Theme toggling: see setup.md.

## Theme scoping

- Dark mode: `.dark` on an ancestor (usually `<html>`). There's no `theme` prop.
- `.inverted` on a subtree renders the opposite theme inside it (e.g. a dark popup on a light page).
- Tokens already switch with the theme. If you're writing `dark:bg-…`, you're probably bypassing a token.

## Icons

- `import { SearchIcon, PlusIcon } from '@blotoutio/design-system'` (or `/icons`). Lucide names + `Icon`.
- Size with `className='size-4'` outside DS components and inside `InputGroup` (unsized Lucide icons are
  24px): `<SearchIcon className='size-4 shrink-0 text-muted-foreground' aria-hidden />`. `Button`, menu
  items and badges size their own icons.
- ⚠️ Lucide names that exist but mean something else: `DeleteIcon` is a backspace key (use `TrashIcon`),
  `EditIcon` is a square-pen (use `PencilIcon` for edit actions).
- Don't install `lucide-react`, `react-icons` or heroicons.

## Version drift

npm can lag Storybook. The installed version is in the app's `package.json`; https://design.blotout.io/api.md
describes the latest. If the installed version lacks a component (typecheck fails on the import),
compose a fallback, flag it, and tell the developer (upgrading is their call). Example: `Chart` is in
the repo but not in 0.1.0.
